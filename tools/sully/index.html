    Sully Slips use the URL fragment so sharing stays static and private to the browser. That means a server cannot make per-track social preview cards from a Slip alone. Proper Open Graph or oEmbed previews need a separate server-backed project.

Getting Started
  1. Read the source and this manual before editing. Shared controls use Base UI.
  2. Serve the repository with a static server. After editing src/ui.jsx, run npm ci and npm run build from tools/sully.
  3. Make the smallest layer-specific change: markup and CSS for a static view, app code for behaviour, protocol code for sharing.
  4. Run focused checks, then use a real Archive item in a browser. A green syntax check cannot tell you whether live metadata is strange today.
  5. Update Docs when a contract changes, append the Log for meaningful behaviour or deployment facts, then deploy coupled assets together.

Do not put credentials here. The handover ledger records where deployment knowledge lives, not secrets themselves.

There is no account, server-side library, queue sync, or hidden recommendation profile. The app asks Archive for public information and keeps only local convenience state in the browser.

Data and Playback: Let Archive Metadata Win

Discovery can begin with an Archive advanced-search result, but a release and playback resolve Archive metadata. That response is the authority for the title, creator, date, rights, and actual file list.

Construct playable URLs from the Archive identifier and the exact metadata file name. A human-facing release title is a label, never a stable audio path. Show a plain failure rather than guessing a nearby URL.

Playback state is one thing at a time: selected track, source URL, audio element, and visible player. Reading Log or Docs must not reset playback or queue state.

Local State: Liked, Queue, History

Individual liked tracks live in IndexedDB under slop-library, store saved. This is per-browser convenience state. Never imply that a link, export, or feature shares it with another person.

Queue and listening history are session behaviour. The easy regression is making a detail dialog or received link unexpectedly write history, clear a queue, or start audio.

When changing local data shape, keep backwards reads tolerant where possible and test an existing browser profile as well as a blank one.

Sully Slip: Exact Sharing Without a New Service

A Slip is a versioned location fragment:

Search matches phrases in credited artists and release titles. The Tags option searches Archive subject tags. Use the search type to narrow the field. Search results use relevance; browsing without a query uses newest uploads. Archive credits can be incomplete. Audio renditions are selected per original recording according to browser support; private files are excluded. Some Archive records contain only bundles or restricted audio.

#v=1&r=archive-identifier&f=relative%2Ftrack.ogg&at=83
  • v=1 is a promise that the format remains readable; do not reinterpret it silently.
  • r is the validated Archive identifier.
  • f is optional for a release-only Slip. When present it must be a relative playable mp3, ogg, m4a, flac, wav, or opus file: no scheme, backslash, control character, absolute path, or dot segment.
  • at is an optional whole-second timestamp, capped at seven days, and only makes sense with f.
  • Labels displayed to the listener come from Archive metadata, never text in a URL.

A release-only Slip opens the release. A track Slip prepares the exact track and seeks once its source is ready, but never autoplays. Keep timestamp listeners bound to the expected source so a later track choice cannot receive an old seek.

Location fragments are not sent to a static server. That is good for this no-account protocol, but per-track social cards and oEmbed discovery are a separate server-backed project if they are ever wanted.

Release Procedure: Change, Check, Say What Happened
  1. Name the user-visible outcome and the invariant that must survive it.
  2. Trace the live path before editing: source, state, player, and public URL contract.
  3. Change the smallest appropriate layer. Avoid unrelated clean-up on a live fix.
  4. Run focused syntax checks, then test a real Archive result and fresh sharing link in a browser.
  5. Update Docs when the stable handover knowledge changed. Append a Log entry for behaviour, reliability, or deployment facts.
  6. Deploy coupled static files together and bump cache suffixes when browsers could otherwise keep mismatched code.
  7. Verify the public functional release in a fresh tab.
  8. Then publish the Log status change from In progress to Shipped in a separate small update and verify the public Log itself.

Troubleshooting: Boring Answers First
A Slip opens the wrong track.
Confirm metadata file name matches f exactly, including nested directories and Unicode. Confirm audio URLs use the Archive identifier, not a displayed release title.
A received Slip suddenly plays.
Check the prepare path passes an explicit no-autoplay flag and a browser user gesture is still required for playback.
The app has old behaviour after deploy.
Look for mismatched cached static assets. Update cache suffixes on files that must ship together and check a fresh tab.
Docs broke a shared track.
Remove hash routing or anchor links. Tabs use the in-app view system, leaving location.hash entirely to Sully Slip.

About Sully

Explore and listen to music from the Internet Archive. Each release links to its original artwork, credits, and rights.

Listening

Select a cover to play an album, or its title to see the tracks. Added tracks play before the rest of the album.

Your Library

Likes and playlists stay in this browser. Back up your library to keep a copy. Backups contain track references, not audio.

Privacy

No account required. Audio streams from the Archive. Shared links include only the selected recording.

Source & Licences

Sully is open source. Recordings retain their original rights.
